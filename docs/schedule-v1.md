# Спецификация контракта ScheduleService (v1)

Документ фиксирует правила взаимодействия, семантику методов, инварианты данных и модель обработки ошибок для сервиса расписания (`orbit.schedule.v1.ScheduleService`) микросервисной экосистемы **Orbit AI**.

Контракт Protobuf:
- [`proto/orbit/schedule/v1/schedule.proto`](../proto/orbit/schedule/v1/schedule.proto) — сервис и структуры данных расписания

---

## 1. Архитектурный обзор

`ScheduleService` предоставляет доступ к расписанию занятий Московского Политеха для клиентов экосистемы Orbit (Web, мобильное приложение Flutter, Telegram-бот).

```
[Клиент (Web / Flutter)] 
       │ 
       ▼
 [API Gateway] ──(gRPC: SearchGroups / GetGroupSchedule)──► [ScheduleService]
                                                                  │
                                                        [PostgreSQL + Redis]
                                                                  ▲
                                                       (Фоновый Syncer)
                                                                  │
                                                        [rasp.dmami.ru]
```

**Ключевые архитектурные принципы:**
1. **Изоляция от внешнего источника:** пользовательские запросы никогда не вызывают прямой синхронный HTTP-запрос к сайту Политеха `rasp.dmami.ru`. Данные всегда читаются из локального хранилища Orbit (PostgreSQL / Redis).
2. **Отказоустойчивость (Stale-While-Revalidate):** при недоступности или сбоях внешнего источника сервис продолжает отдавать последнее сохранённое расписание, явно информируя клиента через флаг `metadata.is_stale = true`.

## 2. Поиск групп (`SearchGroups`)

Метод предназначен для автодополнения и быстрого поиска учебных групп по реестру.

### 2.1. Правила обработки параметров
| Параметр | Тип | Обязательность | Правила и поведение |
| :--- | :--- | :--- | :--- |
| `query` | `string` | Опционально | Регистронезависимый поиск по префиксу и подстроке номера группы. Поддерживает кириллицу, латиницу, дефисы и цифры (например, `"241"`, `"24а-111"`, `"дпо"`). При пустой строке (`""`) возвращаются первые `limit` групп из общего реестра. |
| `limit` | `int32` | Опционально | Максимальное количество записей в ответе. По умолчанию: **20** (если передан `0` или отрицательное число). Максимальное значение: **100** (значения `> 100` автоматически ограничиваются сервером до 100). |

### 2.2. Сортировка результатов
Результаты упорядочиваются стабильно:
1. Точное совпадение (`query == title`);
2. Префиксные совпадения (`title ILIKE query%`);
3. Подстрочные совпадения (`title ILIKE %query%`);
4. Вторичная сортировка по алфавиту названия группы (`title ASC`).

## 3. Флаги и сущность группы (`GroupItem`)

```protobuf
message GroupItem {
  string title = 1;
  bool has_regular_schedule = 2;
  bool has_session_schedule = 3;
}
```

| Поле | Тип | Значение и семантика |
| :--- | :--- | :--- |
| `title` | `string` | Официальный номер/название группы (например, `"241-321"`, `"24А-111"`, `"ДПО-ЦМ2"`). |
| `has_regular_schedule` | `bool` | Доступность семестрового расписания в Orbit:<br>• `true` — расписание успешно получено, сохранено в базе и доступно для чтения;<br>• `false` — расписание ещё не сформировано диспетчерской (источник возвращает «Еще не готово») либо ещё ни разу не загружалось в базу. |
| `has_session_schedule` | `bool` | Признак наличия сессионного расписания экзаменов (соответствует булеву флагу из официального реестра Политеха `groups-list.json`). |

## 4. Запрос расписания группы (`GetGroupSchedule`)

### 4.1. Правила запроса и валидация периода
| Поле | Формат | Обязательность | Описание |
| :--- | :--- | :--- | :--- |
| `group_title` | `string` | **Да** | Номер группы (например, `"241-321"`). Пробелы по краям обрезаются. |
| `date_from` | `YYYY-MM-DD` | **Да** | Начало периода (включительно) по календарю Europe/Moscow. |
| `date_to` | `YYYY-MM-DD` | Нет | Окончание периода (включительно). Если пусто или не передано, запрос считается запросом на **один день** (`date_to = date_from`). |

**Инварианты валидации периода:**
1. Даты должны строго соответствовать формату `YYYY-MM-DD` (ISO 8601 extended).
2. Дата начала не может быть позже даты окончания: `date_from <= date_to`.
3. Максимальная длина интервала составляет **93 календарных дня** (один квартал / 3 месяца). Запросы с периодом более 93 дней отклоняются с ошибкой `INVALID_ARGUMENT`.

## 5. Время, часовой пояс и структура сетки

1. **Часовой пояс:**
   - Все занятия академического расписания привязаны к московскому времени: `Europe/Moscow` (UTC+3).
   - В ответе всегда возвращается явное поле `time_zone = "Europe/Moscow"`.
2. **Время пар (`start_time` / `end_time`):**
   - Передаётся в 24-часовом формате `HH:mm` (например, `"09:00"`, `"10:30"`, `"12:20"`).
   - **Поведение при неизвестной сетке:** если код `evening_type` неизвестен серверу и расписание звонков для него не определено, поля `start_time` и `end_time` возвращаются пустыми строками `""`. Сервер не подставляет фиктивное дневное время.
3. **Дни недели (`day_of_week`):**
   - Нумерация строго по международному стандарту **ISO 8601**:
     `1` — Понедельник, `2` — Вторник, `3` — Среда, `4` — Четверг, `5` — Пятница, `6` — Суббота, `7` — Воскресенье.
4. **Фильтрация дней в ответе (`days`):**
   - Список `days` содержит **только календарные дни, в которые есть хотя бы одно занятие**.
   - Дни без пар (воскресенья, праздники, каникулярные дни) в ответ не включаются, чтобы не раздувать трафик пустыми структурами.
   - Если во всём запрошенном периоде нет ни одной пары, сервер возвращает статус `OK` с пустым списком `days = []`.

## 6. Метаданные синхронизации и актуальности (`ScheduleMetadata`)

```protobuf
message ScheduleMetadata {
  google.protobuf.Timestamp last_checked_at = 1;
  google.protobuf.Timestamp last_updated_at = 2;
  bool is_stale = 3;
}
```

| Поле | Назначение | Условия отсутствия (nil) |
| :--- | :--- | :--- |
| `last_checked_at` | Время последней **успешной** проверки источника `rasp.dmami.ru`. | Отсутствует (`nil`), если группа ещё ни разу не опрашивалась синхронизатором. Неудачные сетевые попытки не обновляют эту метку. |
| `last_updated_at` | Время последнего фактического изменения снимка расписания в БД. | Отсутствует (`nil`), если расписание ещё не сохранялось. При повторных проверках без изменения содержимого метка сохраняет исходное значение. |
| `is_stale` | Признак устаревания данных. | `true`, если с момента `last_checked_at` прошло больше допустимого TTL (по умолчанию 24 часа), либо последняя фоновая попытка обращения к источнику завершилась ошибкой. |

## 7. Модель ошибок и статусы gRPC

| Сценарий | gRPC Status | Сообщение / Поведение |
| :--- | :--- | :--- |
| **Группа не существует** | `NOT_FOUND` | Группа с указанным номером отсутствует в реестре университета. |
| **Расписание не готово** | `UNAVAILABLE` | Группа известна в реестре, но её расписание ещё не сформировано диспетчерской (источник вернул «Еще не готово») либо ещё не загружено сервисом. Клиенту рекомендуется повторить запрос позже. |
| **Некорректный запрос** | `INVALID_ARGUMENT` | Нарушен формат дат (не `YYYY-MM-DD`), `date_from > date_to`, либо интервал превышает 93 календарных дня. |
| **Нет занятий в периоде** | `OK` | Успешный ответ. Список `days` пуст (`len == 0`), метаданные `metadata` заполнены актуальными значениями. |
| **Источник недоступен (Fallback)** | `OK` | Источник `rasp.dmami.ru` недоступен, но в БД Orbit есть сохранённая версия. Возвращается сохранённое расписание со статусом `OK` и флагом `metadata.is_stale = true`. |
