# Спецификация контракта AIService (v1)

Документ фиксирует правила взаимодействия, семантику методов, жизненный цикл потокового диалога, инварианты данных и модель обработки ошибок для сервиса искусственного интеллекта (`orbit.ai.v1.AIService`) экосистемы **Orbit Polytech**.

Контракт Protobuf:
- [`proto/orbit/ai/v1/ai.proto`](../proto/orbit/ai/v1/ai.proto) — сервис диалога и генерации ответов Orbit AI

---

## 1. Архитектурный обзор

`AIService` отвечает за обработку запросов студентов Московского Политеха, взаимодействие с языковыми моделями (LLM), извлечение контекста из базы знаний (RAG) и потоковую выдачу ответов (Server Streaming RPC).

```
[Клиент (Web / Flutter / Telegram)]
                │
                ▼ (HTTP / SSE / WebSocket)
         [API Gateway]
                │
                ▼ (gRPC: ChatStream / CancelGeneration)
           [ai-service]
          ┌─────┴─────────────────────────┐
          │                               │
          ▼                               ▼
    [PostgreSQL + pgvector]       [LLM Provider API]
    (Векторная база знаний /       (Groq Cloud / OpenAI Protocol)
     регламенты Политеха)
```

**Ключевые принципы:**
1. **Потоковая выдача (Streaming First):** ответы пользователю генерируются асинхронно токен за токеном для снижения задержки первого токена (TTFT).
2. **Идемпотентность и управление жизненным циклом:** каждое сообщение и диалог строго идентифицируются уникальными ключами.
3. **Безопасность и конфиденциальность:** сервис не отправляет персональные данные студентов (ФИО, email, пароли) внешним провайдерам LLM.

## 2. Жизненный цикл потока (`ChatStream`)

Метод `ChatStream` использует gRPC Server Streaming: клиент отправляет один запрос `ChatStreamRequest`, а сервер возвращает последовательность сообщений `stream ChatStreamResponse`.

### 2.1. Последовательность этапов (Stage Sequence)

Генерация ответа строго следует детерминированной цепочке стадий (`ChunkStage`):

**Успешный сценарий:**
```
CHUNK_STAGE_START ──► CHUNK_STAGE_DELTA (0..N) ──► CHUNK_STAGE_CITATIONS (0..1) ──► CHUNK_STAGE_DONE
```

**Сценарий сбоя во время стриминга:**
```
CHUNK_STAGE_START ──► CHUNK_STAGE_DELTA (0..N) ──► CHUNK_STAGE_ERROR
```

### 2.2. Описание стадий (`ChunkStage`)

| Стадия (`ChunkStage`) | Значение | Описание и передаваемые поля |
| :--- | :--- | :--- |
| `CHUNK_STAGE_UNSPECIFIED` | `0` | Дефолтное значение Protobuf. Сервер никогда не отправляет это значение. |
| `CHUNK_STAGE_START` | `1` | Первое сообщение стрима. Подтверждает начало генерации, возвращает `conversation_id` и `message_id`. Поле `delta_text` пустое. |
| `CHUNK_STAGE_DELTA` | `2` | Очередная порция сгенерированного текста (один или несколько токенов от LLM). Содержится в поле `delta_text`. Клиент конкатенирует чанки в единый текст. |
| `CHUNK_STAGE_CITATIONS` | `3` | Список ссылок и цитат из базы знаний (`citations`), использованных моделью при подготовке ответа. Отправляется после текста перед завершением или по мере готовности RAG. |
| `CHUNK_STAGE_DONE` | `4` | **Терминальное событие успеха.** Означает, что генерация полностью и успешно завершена. Поле `delta_text` пустое. После отправки этого сообщения сервер закрывает gRPC-поток. |
| `CHUNK_STAGE_ERROR` | `5` | **Терминальное событие ошибки.** Означает непредвиденный сбой во время генерации (например, таймаут провайдера LLM). Содержит `error_code` и `error_message`. После этого сообщения сервер закрывает gRPC-поток. |

### 2.3. Правила терминальных стадий
1. `CHUNK_STAGE_DONE` и `CHUNK_STAGE_ERROR` **взаимоисключающие**.
2. После `CHUNK_STAGE_ERROR` отправка `CHUNK_STAGE_DONE` запрещена.
3. После `CHUNK_STAGE_DONE` отправка `CHUNK_STAGE_ERROR` запрещена.
4. Сервер закрывает поток сразу после отправки любого из терминальных сообщений.

## 3. Модель идентификаторов

```protobuf
message ChatStreamRequest {
  string conversation_id = 1;
  string message_id = 2;
  string query = 3;
  StudentContext context = 4;
}
```

### 3.1. `conversation_id` (Идентификатор диалога)
- **Кто создаёт:** Клиент (Web/Flutter) или API Gateway при создании новой сессии диалога. Формат — UUIDv4.
- **Назначение:** Связывает цепочку запросов и ответов в единый диалог. Используется `ai-service` для загрузки истории предыдущих реплик из базы данных.
- **Правило:** Если клиент передаёт пустой `conversation_id`, API Gateway или сервис генерируют новый UUID и возвращают его в событии `CHUNK_STAGE_START`.

### 3.2. `message_id` (Идентификатор сообщения / попытки генерации)
- **Кто создаёт:** Клиент (Web/Flutter) или API Gateway для каждого конкретного вопроса пользователя. Формат — UUIDv4.
- **Назначение:** Ключ идемпотентности запроса генерации.
- **Семантика повторного запроса:**
  - Если запрос с уже существующим `message_id` приходит, пока предыдущая генерация ещё активна, сервер отклоняет дубликат со статусом `ALREADY_EXISTS` либо подключает клиента к существующему стриму.
  - Если запрос с тем же `message_id` приходит после завершения генерации, сервер не выполняет повторный вызов LLM, а возвращает сохранённый в БД ответ.

## 4. Обработка ошибок

Ошибки разделяются на два уровня в зависимости от момента их возникновения:

### 4.1. Ошибки до начала потока (Pre-stream Errors)
Если ошибка произошла **до** отправки первого чанка `CHUNK_STAGE_START` (например, при валидации входных параметров или проверке авторизации), gRPC-стрим не открывается. Ошибка возвращается стандартным статусом gRPC:

| Ситуация | gRPC Status Code | Описание |
| :--- | :--- | :--- |
| Пустой `query` или длина > 4000 символов | `codes.InvalidArgument` | Некорректный запрос пользователя |
| Некорректный формат UUID (`conversation_id`/`message_id`) | `codes.InvalidArgument` | Невалидный идентификатор |
| Превышен общий лимит запросов пользователя (Rate Limit) | `codes.ResourceExhausted` | Слишком много запросов |
| Ошибка авторизации пользователя | `codes.Unauthenticated` | Отсутствует или невалиден токен |

### 4.2. Ошибки во время потока (Mid-stream Errors)
Если соединение уже установлено и отправлен `CHUNK_STAGE_START` или несколько `CHUNK_STAGE_DELTA`, а затем произошёл сбой (например, провайдер LLM оборвал соединение или вернул 500), сервер отправляет терминальный чанк:

```protobuf
ChatStreamResponse {
  stage: CHUNK_STAGE_ERROR
  error_code: 1001
  error_message: "Сервис генерации временно недоступен. Попробуйте позже."
  conversation_id: "..."
  message_id: "..."
}
```

### 4.3. Реестр доменных кодов ошибок (`error_code`)

| Код (`error_code`) | Символическое имя | Описание |
| :--- | :--- | :--- |
| `0` | `AI_ERROR_NONE` | Ошибок нет. |
| `1001` | `AI_ERROR_UPSTREAM_UNAVAILABLE` | Внешний провайдер LLM недоступен или ответил ошибкой 5xx. |
| `1002` | `AI_ERROR_UPSTREAM_TIMEOUT` | Таймаут ожидания ответа от внешнего провайдера LLM. |
| `1003` | `AI_ERROR_RATE_LIMIT` | Превышен лимит токенов или запросов к API провайдера (429 Too Many Requests). |
| `1004` | `AI_ERROR_CONTEXT_TOO_LARGE` | Суммарный контекст (история диалога + база знаний + запрос) превысил окно контекста модели. |
| `1005` | `AI_ERROR_CONTENT_FILTERED` | Запрос или сгенерированный ответ заблокирован фильтрами безопасности провайдера. |
| `1099` | `AI_ERROR_INTERNAL` | Необработанная внутренняя ошибка микросервиса. |

## 5. Отмена генерации

В процессе выдачи длинного ответа пользователь может нажать кнопку «Стоп» в интерфейсе либо закрыть вкладку браузера/приложение.

Предусмотрено два взаимодополняющих механизма отмены:

### 5.1. Автоматическая отмена через gRPC Context
При закрытии соединения клиентом (SSE / HTTP/2) API Gateway закрывает gRPC-вызов, что переводит gRPC context в состояние `context.Canceled`.
- `ai-service` обязан слушать контекст в цикле чтения LLM-стрима.
- При получении сигнала отмены фоновый запрос к внешнему LLM API немедленно прекращается (вызывается `stream.close()` / `aclose()`). Это исключает лишний расход токенов провайдера.

### 5.2. Явный RPC-метод `CancelGeneration`

```protobuf
rpc CancelGeneration(CancelGenerationRequest) returns (CancelGenerationResponse);

message CancelGenerationRequest {
  string conversation_id = 1;
  string message_id = 2;
}

message CancelGenerationResponse {
  bool cancelled = 1;
}
```

- Вызывается клиентом для явной остановки процесса генерации по паре `(conversation_id, message_id)`.
- **Семантика поля `cancelled`:**
  - `true` — активная задача генерации найдена в менеджере задач сервиса и успешно остановлена.
  - `false` — задача с указанными идентификаторами не найдена (уже завершилась ранее, была отменена другим запросом или не существовала).
- Метод идемпотентен: повторные вызовы `CancelGeneration` с теми же идентификаторами безопасны и всегда возвращают `cancelled = false` без ошибок.

## 6. Контекст студента (`StudentContext`) и безопасность

```protobuf
message StudentContext {
  string group_title = 1;
  string faculty = 2;
  int32 course = 3;
}
```

1. **Семантика контекста:**
   - Поля `group_title`, `faculty`, `course` являются **подсказкой (advisory hint)** для системного промпта LLM. Они помогают модели давать адресные ответы (например: подставлять номер группы при запросе расписания или регламентов факультета).
2. **Недоверенный источник:**
   - Данные из `StudentContext` **не являются основанием авторизации** и не подтверждают принадлежность пользователя к группе или факультету.
   - Сервис `ai-service` не использует эти поля для проверки прав на доступ к приватным данным.
3. **Защита персональных данных (ПДн):**
   - В `StudentContext` и запросах к LLM запрещено передавать персональные данные (ФИО студента, номер зачётной книжки/студенческого, номер телефона, email).
   - Внешнему провайдеру отправляется обезличенный академический контекст.
