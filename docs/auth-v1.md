# Спецификация контракта AuthService (v1)

Документ фиксирует правила взаимодействия, семантику методов, инварианты данных и модель обработки ошибок для сервиса аутентификации (`orbit.auth.v1.AuthService`) микросервисной экосистемы **Orbit AI**.

Контракты Protobuf:

- [`proto/orbit/auth/v1/auth.proto`](../proto/orbit/auth/v1/auth.proto) — сервис и методы Email OTP
- [`proto/orbit/auth/v1/oauth.proto`](../proto/orbit/auth/v1/oauth.proto) — операции входа через OAuth 2.0 / OIDC
- [`proto/orbit/auth/v1/identity.proto`](../proto/orbit/auth/v1/identity.proto) — управление внешними идентичностями (Identity Linking)

---

## 1. Архитектурный обзор

`AuthService` отвечает за первичный вход пользователей по одноразовым кодам (OTP), вход через внешних провайдеров (OAuth 2.0 / OIDC: Google), управление привязанными идентичностями, ротацию сессий и выпуск токенов Ed25519.

```
[Клиент (Web / Flutter)]
       │
       ▼
 [API Gateway] ──(Request context: client_ip, user_agent, user_id)──► [AuthService]
                                                                            │
                                                                   [PostgreSQL + Redis]
```

---

## 2. Формат и правила одноразовых кодов (OTP)

1. **Формат кода:** строка ровно из **6 десятичных цифр** (`^[0-9]{6}$`). Тип — `string` (сохраняет ведущие нули).
2. **Время жизни (TTL):** по умолчанию 300 секунд (5 минут), возвращается в `SendCodeResponse.expires_in_seconds`.
3. **Однократность:** после успешной проверки в `VerifyCode` код немедленно удаляется.
4. **Повторная отправка:** предыдущий код аннулируется только при принятом запросе на новый выпуск. Cooldown фиксируется в `retry_after_seconds` (по умолчанию 60 сек).

---

## 3. Сессии и ротация Refresh-токенов (Token Family)

1. **Модель токенов:**
    - **Access Token:** короткоживущий JWT (Ed25519, 15 минут). Проверяется Gateway stateless. Содержит claims: `sub` (account_id), `auth_time` (время реального подтверждения личности).
    - **Refresh Token:** долгоживущий непрозрачный токен (30–60 дней). В БД хранится только хэш SHA-256.
2. **Атомарная однократная ротация (Token Family):**
    - Вызов `RefreshToken` атомарно аннулирует использованный токен и выдаёт новую пару.
    - Повторное использование старого токена расценивается как кража сессии: всё семейство токенов немедленно отзывается (`Unauthenticated`).
3. **Ограничение клиента:** клиент выполняет не более одного запроса refresh одновременно и не повторяет его автоматически при таймауте.

---

## 4. Поведение выхода из системы (Logout)

1. **Идемпотентность:** метод `Logout` всегда возвращает `OK`, даже если токен уже истёк или был отозван.
2. **Действие Access JWT:** `Logout` отзывает сессию в БД. Уже выданный Access JWT остаётся валидным до своего естественного истечения (до 15 минут).

---

## 5. Клиентский контекст (Client IP & User-Agent)

1. Поля `client_ip` и `user_agent` заполняются **исключительно доверенным API Gateway**.
2. Данные используются для аудита безопасности и отображения списка активных устройств.

---

## 6. Вход через внешних провайдеров (OAuth 2.0 / OIDC)

### 6.1. Жизненный цикл операции входа (`BeginOAuthLogin` / `FinishOAuthLogin`)

1. **Инициализация (`BeginOAuthLogin`):**
    - Gateway генерирует криптографически стойкую строку `initiator_binding` (32 байта base64url).
    - Gateway вызывает `BeginOAuthLogin(provider, client_type, initiator_binding)`.
    - `AuthService` генерирует PKCE code_verifier, code_challenge (S256), OIDC nonce и анти-CSRF токен `state` с префиксом `login_`.
    - Вся транзакция сохраняется в Redis с TTL = 5 минут:
      `oauth:txn:<state>` $\to$ `{intent: "login", provider, code_verifier, initiator_binding_hash, client_type}`.
    - Gateway выставляет браузеру временную cookie: `HttpOnly`, `SameSite=Lax`, `Secure` (в prod), `Path=/api/v1/auth/oauth` со значением `initiator_binding`.
2. **Завершение (`FinishOAuthLogin`):**
    - Провайдер возвращает пользователя на зарегистрированный GET callback Gateway.
    - Gateway считывает cookie `initiator_binding` и передаёт её вместе с `code` и `state` в `FinishOAuthLogin`.
    - `AuthService` атомарно извлекает и удаляет транзакцию из Redis (однократность).
    - `AuthService` сверяет хэш переданного `initiator_binding` с сохранённым в транзакции. При несовпадении операция отклоняется (`Unauthenticated`).
    - `AuthService` обменивает `code` на ID Token провайдера, валидирует подпись по JWKS, срок действия, `iss`, `aud` и `nonce`.
    - `AuthService` возвращает выпущенные токены Orbit и доверенный `client_type`.
    - Для Web-режима Gateway устанавливает `refresh_token` HttpOnly cookie и редиректит пользователя на чистый URL фронтенда без токенов в query.

### 6.2. Идентификация и отказ от автоматического связывания по email

1. Пользователь идентифицируется **исключительно по стабильному идентификатору** `(provider, provider_subject)`.
2. **Запрет неявного слияния:** совпадение подтверждённого `email` из Google с существующим аккаунтом в Orbit **не приводит к автоматическому связыванию**.
3. Если внешняя идентичность не найдена:
    - Если email свободен $\to$ регистрируется новый аккаунт Orbit и привязывается идентичность (`is_new_user = true`).
    - Если аккаунт с таким email уже существует $\to$ сервис отклоняет вход с требованием подтвердить владение существующим аккаунтом через OTP (`FailedPrecondition`).

## 7. Управление внешними идентичностями (Identity Linking)

### 7.1. Подключение способа входа (`BeginIdentityLink` / `FinishIdentityLink`)

1. **Авторизованный контекст:** метод `BeginIdentityLink` требует активной сессии пользователя (`user_id` извлекается Gateway из проверенного Access Token).
2. **Подтверждение личности (`reauth_proof`):**
    - Поле `reauth_proof` содержит Access JWT текущего пользователя.
    - Токен обязан содержать claim `auth_time` (момент реальной аутентификации). При refresh токена `auth_time` не обновляется.
    - Требование: `now() - auth_time <= 300 секунд` (5 минут). При превышении окна возвращается `Unauthenticated` (_«Требуется повторное подтверждение личности»_).
3. **Фиксация целевого аккаунта:**
    - На этапе `Begin` Auth-сервис сохраняет `target_account_id = user_id` в Redis транзакции (`state` имеет префикс `link_`).
    - На этапе `FinishIdentityLink` от клиента **не требуется передача `user_id`**. Сервер берёт целевой аккаунт из проверенной транзакции в Redis.

### 7.2. Защита от отключения последнего способа входа (`UnlinkIdentity`)

1. Запрос `UnlinkIdentity` требует передачи актуального `reauth_proof`.
2. **Инвариант:** у пользователя всегда должен оставаться хотя бы один способ входа (подтверждённый email для OTP или другой привязанный провайдер).
3. Попытка удалить последний способ входа отклоняется с кодом `FailedPrecondition` (_«Нельзя отключить единственный способ входа»_).
4. **Атомарность:** проверка числа способов входа и удаление выполняются внутри единой транзакции PostgreSQL с взятием блокировки:
   `SELECT pg_advisory_xact_lock(hashtext('account_identities:' || account_id::text));`

## 8. Стандартизированные коды ошибок gRPC

| Код ошибки               | Canonical gRPC Code            | Когда возвращается                                                                                                                                                                        |
| :----------------------- | :----------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`InvalidArgument`**    | `codes.InvalidArgument` (3)    | Некорректный email, неверный формат OTP (длина != 6), пустые обязательные поля (`code`, `state`).                                                                                         |
| **`Unauthenticated`**    | `codes.Unauthenticated` (16)   | Неверный или истёкший OTP; несовпадение `initiator_binding`; недействительный ID Token провайдера; истёкший `reauth_proof` (> 5 минут).                                                   |
| **`AlreadyExists`**      | `codes.AlreadyExists` (6)      | Попытка привязать Google-аккаунт, который уже подключен к **другому** аккаунту Orbit (без раскрытия чужого профиля).                                                                      |
| **`FailedPrecondition`** | `codes.FailedPrecondition` (9) | 1) Email из соцсети совпадает с существующим аккаунтом без предварительной связи.<br>2) К аккаунту уже подключен другой Google.<br>3) Попытка отключить последний доступный способ входа. |
| **`PermissionDenied`**   | `codes.PermissionDenied` (7)   | Аккаунт заблокирован (`is_blocked = true`).                                                                                                                                               |
| **`ResourceExhausted`**  | `codes.ResourceExhausted` (8)  | Превышен лимит запроса OTP (cooldown) или исчерпаны попытки ввода.                                                                                                                        |
| **`Unimplemented`**      | `codes.Unimplemented` (12)     | Запрос нереализованного провайдера или режима (`CLIENT_TYPE_MOBILE`).                                                                                                                     |
| **`Unavailable`**        | `codes.Unavailable` (14)       | Сбой сети, недоступность БД или провайдера авторизации.                                                                                                                                   |
